# WB FBS Automation

Автоматизация FBS Wildberries: **один заказ → одна поставка → документы PDF → Telegram**. Сервисный центр: **Кавказский бульвар**. Независимый проект; не связан с другими проектами WB.

## Текущий этап: V0.1, только чтение

- Cloudflare Worker автоматически публикуется из ветки `main` через Cloudflare Builds.
- `GET /health` — публичная проверка запуска без обращения к WB.
- `GET /diagnostics` — защищённая проверка API WB: склады, новые заказы, поставки, пункты для пропусков. Возвращаются только сводные данные, без персональных данных покупателей.
- **Нет автоматического создания поставок, отправки в доставку или сообщений в Telegram.**
- Дата отгрузки и маршрут перехода «Передать в доставку» требуют проверки по реальному сценарию в кабинете WB. Не подставлять фиктивные даты.

## Секреты Cloudflare

В Worker → Settings → Variables and Secrets добавить тип **Secret**:

- `WB_API_TOKEN` — персональный токен WB с доступом к категории «Маркетплейс».
- `ADMIN_KEY` — независимый случайный ключ для диагностического API.

Создать `ADMIN_KEY` локально на Mac, сразу скопировав в буфер обмена:

```sh
openssl rand -hex 32 | pbcopy
```

Не отправлять значения секретов в чат и не коммитить их в GitHub.

## Как проверить

1. В Cloudflare → Worker → Deployments убедиться, что последняя сборка **Ready**.
2. Нажать **Visit** и добавить `/health` к адресу Worker. Ожидается JSON с `"ok":true`.
3. После добавления обоих секретов можно проверить `/diagnostics` из терминала Mac, не публикуя ADMIN_KEY:

```sh
read -s "KEY?ADMIN_KEY: "; echo
curl -sS -H "X-Admin-Key: $KEY" "https://ВАШ-АДРЕС-WORKER/diagnostics"
unset KEY
```

Вместо `https://ВАШ-АДРЕС-WORKER` вставить адрес из кнопки Visit. **Не вставлять в чат секреты или полные заголовки запросов.** Достаточно сводного JSON ответа; он не должен содержать личных данных покупателей.

## Принципы безопасности

- Только официальный WB API, без обхода требований WB.
- До явного включения записи все операции read-only.
- Не создавать поставки-дубликаты; перед будущим запуском добавить идемпотентность и D1.
- Не отправлять QR/PDF до подтверждения их корректности.
- Не хранить WB API токены в GitHub, логах, URL.
